# Veniceのi18n方針

## jaとenを必須にし、他言語の不足キーは英語へ戻す

UI文言は日本語（ja）と英語（en）だけを埋める。12言語すべてを埋め続ける運用はやめる。
UI追加のたびに12ファイルを編集する手間と、上流マージ時の衝突を減らすため。

他言語のカタログと既存の翻訳、言語選択は残す。選択言語にキーがあればその翻訳を使い、
無ければ英語カタログ、英語にも無ければキーへフォールバックする。
renderer-i18n / extension-i18n / main-textsのカタログ完全性はjaとenだけを必須とする。

## 既存のi18n経路を使う

- rendererの`t()`は選択言語 → `en.json` → sourceキーの順で解決し、`ui()`の再描画にも適用する。
  カタログに欠けた複数形には英語の複数形規則を使う。
- 拡張の`t()`も、アプリ指定言語で欠けたキーは英語へ戻す。Chromeの別の言語へ切り替えない。
  アプリがまだ言語を指定していない場合のChrome言語は維持する。
  既存の`t(key, English fallback, substitutions)`の英語source引数も互換のため保持し、引数も無ければキーを返す。
- mainのtray・通知・native dialogは、既存どおりrendererの訳を受け取り、未受信・未登録時は英語sourceを使う。

文字列は必ず`t()` / `ui()`経由でカタログに置き、コードへ直書きしない。
ja.jsonの既存日本語キーも残し、en.jsonに対応する英語sourceを登録する。
この規律を守れば、後から言語を足す作業はカタログのデータ追加だけで済む。
